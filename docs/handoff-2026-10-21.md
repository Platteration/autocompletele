## Security review of 21 October 2026

Method: a workflow of 114 agents over the 97 changed files. Nine finders with
distinct lenses (filesystem and paths, parsers of outside input, the policy as
an attacker, data leakage, the Electron shell and IPC, the Sheets add-in,
typing and command injection, the engine and learning, supply chain) produced
42 raw findings, merged to 33 unique. Each unique finding was then put to three
independent verifiers (reproduce it, judge scope and impact against
`SECURITY.md`, refute it); a finding survived when at least two said real and in
scope. A usage limit stopped the run before it finished: 22 findings were fully
verified (21 confirmed, 1 rejected), 11 were not verified at all, the second
finder round and the written report never ran. The finders also listed 132
attack paths they tested and found closed.

### Fixed on this branch (commit after the review)

| Finding | Severity | Fix |
| --- | --- | --- |
| Decompression bomb: a small `.docx`/`.xlsx` in a watched folder inflated without bound and took the desk down | high | `core/extract.js` caps what one ZIP entry may inflate to (`LIMITS.maxInflatedBytes`, 32 MiB); over the cap the file is "unreadable", as a corrupt file is. |
| A Sheets block of about 130,000 rows threw a RangeError out of the policy parser, so a signed policy stopped the desk from starting | high | `core/sheets.js` refuses by row count before looking at rows and folds the width instead of spreading it; `core/org-policy.js` turns any throwing suite normaliser into a warning and an empty section. |
| A filing blank named like an Object member (`[[constructor]]`) crashed `propose` and the admin tool | medium | `core/filer.js` looks fields up with `Object.hasOwn`. |
| A filing pattern could pull a card number or labelled secret out of a document into the file name, the index, the audit log and a notification | medium | Detected and answered values that the scrubber would mask are left as blanks for the person; values are capped at 80 characters. |
| A symbolic link dropped in a watched folder was read, mined and, across devices, its target copied out | medium | `desktop/assistant.js` and `desktop/filer.js` use `lstat` and skip links; `moveFile` refuses them. |
| The filing queue recursed once per file without a proposal and ran from a timer with no `try/catch` | medium | `desktop/main.js` drains the queue in a loop and logs a throwing proposal. |

### Confirmed and still open, in the order to take them

1. **Policy regular expressions can hang the desk (high).** Patterns from the
   policy (guard `internalCodes` and rule patterns, forms `keyPattern` and
   titles, reply extractors, filing fields, sheets column rules) are checked
   for syntax only and run on every keystroke or word end. A catastrophic
   pattern freezes the main process from the person's own typing, and the
   add-in pane the same way. Fix at normalise time: refuse nested or adjacent
   unbounded quantifiers and cap pattern length, with a policy warning; cap the
   text the patterns see (titles, keys, headers, clipboard); and give the
   keystroke path a time budget or a worker with a hard timeout. The same
   class exists in `capture-policy.js` title patterns (pre-existing). Make
   `actle-admin validate` refuse the same.
2. **"Never overwrites" is a check-then-rename (medium).** `applyFiling` and
   `admin file --apply` check `existsSync` then rename; a file created in
   between is replaced. Reserve the target atomically (`fs.linkSync` then
   unlink, or `openSync(target, "wx")`) and retry the next number on `EEXIST`.
   Add a test that creates the target between the check and the move.
3. **Forms sessions and own records are stored in clear text (medium).**
   `apps/forms.json` holds typed answers and lookup rows outside the encrypted
   corpus, retention and "Delete learned text". Seal them with the corpus box
   the store already holds (or refuse to store without a keychain), prune with
   `retention.corpusDays`, delete in `clearLearning`, and say exactly what the
   file holds in the docs until then.
4. **The filing popover takes keyboard focus when a file lands (medium).** A
   document arriving while the person types steals the caret, with Name
   selected and Enter bound to "File it". Show it without focus
   (`showInactive` or `focusable: false` until clicked) or notify and open from
   the tray.
5. **A shared workbook's configuration silently replaces the organisation's
   in the Sheets pane (medium).** Treat a document-carried configuration as
   untrusted: keep the organisation's copy, offer the document's only after a
   confirmation that shows what changes, never write it to `localStorage`
   unasked; longer term sign the exported section with the policy key.
6. Low: `admin file` does not expand `~` or resolve relative folders like the
   desk does, and moves directories; the 150-character name cap counts UTF-16
   units and can split a surrogate pair, folder components have no cap; undo
   moves whatever is at the filed path now (store size and mtime in the index
   and refuse when they differ); the Windows reserved-name check misses
   `CON.x.txt`; data files are written with the default umask (write
   `0o600`, folders `0o700`, chmod on start); own-record labels built from
   typed values reach OS notifications; `settings:save` accepts any key from
   the renderer (allow-list and coerce), `filing:reveal` any path (take an
   index id), and the windows have no navigation guards; "Never for this
   folder" from a sub-folder of a recursive watch does nothing; Sheets block
   rows are not formula-guarded.

### Not verified (the limit stopped the verifiers)

Each of these is one finder's claim; verify before acting:

- Guard's "Copy corrected text" copies the whole typed field, other rules'
  secrets included, and the sender's clipboard restore does not cover it.
- App extension hooks and `handleAction` run inside the global key callback
  with no `try/catch`; one throwing app could stop expansion.
- The sender restores the clipboard on a 600 ms timer that can fire before a
  slow paste lands.
- Forms, Reply and Notes type into whichever window has the focus when the
  popover closes; only Guard refuses after a focus change.
- A document named `--apply` in a folder turns an `admin file` dry run into a
  real move (argv parsing); other flags likewise.
- Undo and trigger deletion count UTF-16 units, so an emoji in the trigger
  removes one character too many.
- `sender.press("constructor")` reaches a prototype member of the key table.
- Guard keeps and, on Fix, copies text typed in terminals and password
  managers (does capture mode "off" stop app checks? the engine returns no
  actions in mode off, so this is probably refuted; check).
- The send gesture is never checked: a secret as the last token before Enter
  is missed.
- A popover opened before the organisation paused the desk still pastes.
- Forms' secret filter is narrower than Guard's detectors (IBANs, national
  IDs, differently named fields).
- `node --test` runs `sheets-addin/test/fakes.js` as a test file (hygiene).

### Rejected after verification

- Guard clipboard fix leaking other rules' findings was judged the same root
  cause as the unverified clipboard item above; treat the two together.

### What the finders ruled out (coverage)

Path traversal through filing values and folder templates (values are
cleaned of separators, folders resolve under the document's folder);
SendKeys and osascript injection (text travels through the clipboard, only
key codes go through the scripting tools); inline scripts and handlers in
the new HTML (CSP `default-src 'self'`, `textContent` everywhere); the
`app:invoke` bridge reaching channels outside an app's prefix; typed text in
metrics, usage reports or audit lines; policy regexes used in `new
RegExp` with user text as the pattern; prototype pollution through policy
JSON into shared objects (normalisers copy field by field); formula injection
from vocabularies and completions (guarded); network access from the add-in
build; new runtime dependencies (none); real-looking secrets in fixtures
(test card numbers and fake IBANs only).

### Limits of this review

No Electron, Excel or Google host was run, so the shell findings rest on
reading `main.js` and the renderer code. Round two of the finders (outside
input variants, desk-side races, promises versus code, availability) did not
run. The verification of eleven findings did not run. A follow-up should
resume the workflow after the limit resets (the orchestration script and run
id are in the session that produced this page) or re-verify the list above by
hand.
